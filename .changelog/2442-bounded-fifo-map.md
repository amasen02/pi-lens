- **`BoundedFifoMap<K,V>` sibling of `BoundedLruCache` (refs #2442)** — `clients/bounded-cache.ts` shipped only a true-LRU bounded map, so every FIFO-shaped bounded cache in the repo hand-rolled the same `map.keys().next().value` evict-oldest block instead. #2432's round-3 review named two such sites; a repo-wide sweep found the idiom 27 times. `BoundedFifoMap` never re-inserts on `get` and never reorders an already-present key on `set` — insertion order stays eviction order, matching native `Map` semantics exactly, so a caller that wants a write to refresh recency does its own `delete`+`set` around it. Both bounded classes' `set()` now return the evicted keys (oldest first) so eviction-side bookkeeping (telemetry, tombstone sets, WASM-tree retirement) no longer needs the banned idiom either. 20 of the 27 sites migrated (17 to `BoundedFifoMap`, 3 to `BoundedLruCache` where `get` genuinely re-inserts); 3 are deferred (owned by an in-flight `clients/review-graph/*` fix) and 3 are "neither" (a `PathKeyedMap` variant and `tree-sitter-cache.ts`'s WASM-retiring LRU, both needing a bounded-map shape this issue's minimal scope doesn't cover) — see the PR body's full per-site verdict table. A new `tests/config/bounded-eviction-idiom-sweep.test.ts` sweep forbids a new hand-rolled instance of the idiom outside `clients/bounded-cache.ts`.
